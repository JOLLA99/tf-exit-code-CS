## [ROLE-001] 클라우드 컴퓨팅이 무엇이고, 온프레미스 환경과 어떤 차이가 있는지 설명해 주세요.

답변:

클라우드 컴퓨팅은 IT 자원을 직접 소유하지 않고 클라우드 인프라에서 필요한 만큼 빌려 쓰는 방식이고, 온프레미스는 자체 데이터센터에 직접 구축해 운영하는 방식입니다. 온프레미스는 장비를 미리 구매하는 선투자 구조라 증설이 느린 반면, 클라우드는 사용량 기반 과금이라 몇 분 만에 자원을 늘리고 줄일 수 있습니다. 다만 데이터를 사내, IDC에 둬야 하며, 부하가 일정해 장기 비용이 더 큰 경우엔 온프레미스가 유리해, 실무에서는 하이브리드도 많습니다.

참고 자료:
- https://velog.io/@ohback/On-Premises-vs-Cloud

## [ROLE-002] IaaS, PaaS, SaaS의 차이를 설명해 주세요.

답변:

셋은 인프라 스택의 어느 계층까지 사업자가 책임지느냐에 따른 구분입니다. IaaS는 가상 서버까지 제공하고 OS와 애플리케이션은 사용자가 관리하며, PaaS는 실행 환경까지 제공해 코드에만 집중하게 하고, SaaS는 완성된 소프트웨어를 그대로 제공합니다. 위로 갈수록 관리 부담은 줄지만 통제 범위와 자유도도 줄어, 무엇을 직접 통제해야 하는지로 선택합니다.

## [ROLE-004] 클라우드에서 Region과 Availability Zone이 무엇인지 설명해 주세요.

답변:

리전은 사업자가 데이터센터를 모아 서비스를 제공하는 지리적 단위이고, 가용 영역(AZ)은 리전 안에서 독립된 전원과 네트워크를 갖는 물리 데이터센터 묶음입니다. AZ들은 물리적으로 떨어져 있어 한 AZ에 장애가 나도 다른 AZ는 멀쩡하면서, AZ 간은 지연이 짧은 전용망으로 연결돼 동기 복제가 가능합니다. 그래서 고가용성을 위해 자원을 최소 두 개 이상의 AZ에 분산하는 것이 원칙입니다.

## [ROLE-005] VPC가 무엇이고, 클라우드 네트워크에서 어떤 역할을 하는지 설명해 주세요.

답변:

VPC는 퍼블릭 클라우드 안에 논리적으로 격리된 사용자 전용 가상 네트워크로, CIDR로 사설 IP 대역을 정하고 서브넷과 라우팅 테이블, 게이트웨이를 직접 설계합니다. 내부 대역을 향하는 로컬 라우팅이 기본 생성돼 서브넷 간 통신은 바로 되고, 외부와 통신하려면 인터넷 게이트웨이를 붙이고 0.0.0.0/0 경로를 추가해야 합니다. 결국 네트워크 경계를 직접 그어 통신 범위와 외부 노출 수준을 통제하는 역할입니다.

## [ROLE-007] Security Group과 Network ACL의 차이를 설명해 주세요.

답변:

보안 그룹은 인스턴스 단위, 네트워크 ACL은 서브넷 단위로 동작하는 방화벽입니다. 가장 큰 차이는 상태 추적으로, 보안 그룹은 stateful이라 허용된 요청의 응답은 자동으로 나가지만 네트워크 ACL은 stateless라 응답도 반대 방향 규칙에서 따로 허용해야 합니다. 또 보안 그룹은 허용 규칙만 두는 반면, 네트워크 ACL은 거부 규칙도 쓸 수 있고 번호가 낮은 규칙부터 평가됩니다.

## [ROLE-008] NAT Gateway가 무엇이고, 어떤 상황에서 사용하는지 설명해 주세요.

답변:

NAT 게이트웨이는 프라이빗 서브넷의 인스턴스가 외부로 나가는 통신은 하되 외부에서 먼저 연결을 여는 것은 막아 주는 서비스입니다. 프라이빗 라우팅에 0.0.0.0/0을 NAT로 향하게 하면 NAT가 출발지 주소를 자기 공인 IP로 바꿔 대신 통신해 줍니다. 주로 프라이빗 서버가 보안 패치나 외부 API 호출을 할 때 쓰며, 생성만 해도 요금이 계속 발생해 비용 점검 시 우선 확인 대상입니다.

참고 자료:

## [ROLE-009] Load Balancer가 무엇이고, L4 Load Balancer와 L7 Load Balancer의 차이를 설명해 주세요.

답변:

로드 밸런서는 트래픽을 여러 서버에 나눠 부하를 분산하고, 헬스 체크로 비정상 서버를 빼 가용성을 높이는 장치입니다. L4는 전송 계층에서 IP와 포트만 보고 분산해 빠르지만 요청 내용을 해석하지 않아 라우팅이 제한적이고, L7은 URL이나 헤더까지 해석해 경로별로 다른 서버 그룹에 보내는 유연한 라우팅이 가능한 대신 비용이 큽니다.

## [ROLE-010] Auto Scaling이 무엇이고, 어떤 기준으로 확장 또는 축소할 수 있는지 설명해 주세요.

답변:

오토 스케일링은 부하에 따라 인스턴스 수를 자동으로 조절해 성능과 비용을 함께 관리하는 기능으로, 최소와 희망, 최대 용량 범위 안에서 조정합니다. 조정 기준은 보통 모니터링 지표 알람으로, CPU 사용률 같은 대표 지표의 목표값을 유지하도록 조정하고 예측되는 트래픽에는 예약 방식으로 대응합니다. CPU 외에 요청 수나 큐 길이 같은 지표도 쓸 수 있고, 헬스 체크와 연동해 비정상 인스턴스를 교체하기도 합니다.

참고 자료:

## [ROLE-014] CDN이 무엇이고, 정적 리소스 제공에 어떤 장점이 있는지 설명해 주세요.

답변:

CDN은 전 세계에 분산한 엣지 서버에 원본 콘텐츠 사본을 캐싱해 두고 사용자와 가장 가까운 서버에서 응답하게 하는 콘텐츠 전송 네트워크입니다. 이미지나 CSS, JS처럼 자주 안 바뀌는 정적 파일은 한 번 캐싱하면 만료 전까지 오리진에 갈 필요가 없어 응답 지연과 오리진 부하, 트래픽 비용이 함께 줄어듭니다. 다만 캐시 때문에 새 배포가 안 보일 수 있어 TTL과 캐시 무효화, 파일명 해시를 함께 설계해야 합니다.

## [ROLE-018] Kubernetes의 Pod, Deployment, Service의 역할을 설명해 주세요.

파드는 배포의 최소 단위로, 하나 이상의 컨테이너가 같은 네트워크와 IP를 공유하며 localhost로 통신하는 묶음입니다. 디플로이먼트는 파드를 선언형으로 관리해 지정한 개수를 유지하고, 버전 변경 시 롤링 업데이트를, 문제 시 롤백을 수행합니다. 서비스는 파드가 새로 뜰 때마다 IP가 바뀌는 문제를 해결하려고 레이블로 파드를 묶어 고정된 이름과 가상 IP를 제공하므로, 파드 IP를 직접 참조하지 않고 서비스를 거칩니다.

## [ROLE-019] CI/CD가 무엇이고, 빌드-테스트-배포 파이프라인의 흐름을 설명해 주세요.

답변:

CI는 변경한 코드를 자주 병합하고 병합할 때마다 자동으로 빌드와 테스트를 실행해 충돌이나 회귀를 조기에 잡는 방식입니다. CD는 지속적 제공과 배포를 함께 가리키는데, 앞은 배포 가능한 산출물을 만들어 두고 프로덕션 반영만 수동 승인으로 남기고, 뒤는 그 승인까지 없애 자동 배포합니다. 파이프라인은 커밋, 빌드, 자동 테스트, 이미지 생성, 스테이징 검증, 프로덕션 배포 순이며 어느 단계든 실패하면 중단하고 알림이 갑니다.

## [ROLE-020] 무중단 배포가 무엇이고, Blue-Green 배포와 Rolling 배포의 차이를 설명해 주세요.

답변:

무중단 배포는 새 버전을 반영하는 동안에도 요청이 항상 정상 인스턴스로만 가도록 해 중단 없이 배포하는 방식입니다. 롤링 배포는 인스턴스를 일부씩 빼고 새 버전으로 교체하기를 반복해 추가 자원이 거의 안 들지만, 배포 중 처리 인스턴스가 줄고 신구 버전이 공존해 호환성 문제가 생길 수 있습니다. 블루-그린은 같은 규모의 그린 환경을 따로 두고 트래픽을 한 번에 전환해 롤백이 빠른 대신, 두 환경을 유지해 비용이 약 두 배가 됩니다.
